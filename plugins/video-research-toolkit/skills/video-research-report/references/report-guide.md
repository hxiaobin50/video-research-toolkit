# Markdown视频调研报告规则

## 一、报告目的

报告要解释“发现了什么、为什么可信、还有什么不确定、接下来能做什么”，不能只是复述Excel行数或罗列热门视频。

报告可以只覆盖视频内容、只覆盖VOC或综合两者。章节根据研究问题调整，不要求固定数量。

## 二、最低组成

无论报告范围如何，至少包括：

1. 研究问题与范围；
2. 平台、时间、样本和方法；
3. 主要发现及数据支持；
4. 原视频、原评论或证据ID；
5. 反例、争议和替代解释；
6. 数据缺失与结论边界；
7. 结论、优先级和可落地建议。

## 三、证据分析链

每个重要结论依次回答：

```text
观察到什么数据或原声
→ 它能支持什么判断
→ 它不能支持什么
→ 是否有其他合理解释
→ 是否存在反例或平台差异
→ 对消费者理解或内容执行有什么启示
→ 还需要怎样验证
```

将事实、AI归纳、推断和建议明确区分。

## 四、视频内容分析

有视频内容数据时，按研究问题选择分析：

- 平台内容供给及主要主题；
- 不同旅程阶段和用户任务的覆盖；
- 长视频与短视频的主题、结构和表现差异；
- 高表现内容的共同机制与不可复制条件；
- 人工观看发现的开头、结构、演示、表达、拍摄和行动引导；
- 高播放、强互动和高质量评论是否指向同一内容；
- 普遍做法、少见做法和证据支持的内容缺口。

“长视频怎么拍受欢迎”“短视频怎么拍受欢迎”等综合结论在报告中形成，必须说明比较组和证据。

## 五、VOC分析

有评论数据时，按研究问题选择分析：

- 主要用户任务、问题、需求和判断；
- 需求主题的评论数量、独立视频数量和方向；
- 评论点赞所反映的语境内共鸣；
- 代表原声与重要反例；
- 消费者旅程阶段、流转和信息缺口的校准；
- 需求严重度、影响范围和行动影响；
- 技术、安全或质量观点中需要专业确认的部分。

## 六、内容信任分析

内容信任不强制归入旅程。报告可以单列：

- 消费者如何评价信息清晰度和完整度；
- 演示、画面、剪辑、字幕和声音如何影响理解；
- 演讲者或创作者的可信与质疑来源；
- 广告、种草、带货或利益关系如何影响接受；
- 专业纠错、事实争议与评论回复如何改变信任；
- 哪些内容元素值得保留、改进或验证。

## 七、供给与需求交叉分析

视频内容与VOC同时存在时，重点识别：

- 消费者关注且平台内容充分覆盖的主题；
- 消费者关注但内容覆盖不足的主题；
- 内容很多但消费者反馈弱或存在质疑的主题；
- 高表现视频与高频VOC是否一致；
- 某平台擅长解决哪些任务，哪些判断仍缺证据；
- 内容机会来自真实需求、表达方式还是创作者/分发偶然性。

机会必须写明：消费者问题、现有供给、证据、建议形式、限制和验证方式。

## 八、Markdown链接与图表

- 使用`[描述文字](原链接)`，不要在正文堆放长URL；
- 表格中的视频标题、评论证据ID或来源名称可以直接设置为链接；
- 本地Excel可使用相对路径链接，确保报告和outputs目录一起移动时仍可打开；
- 图表只用于明显提高理解的分布、比较、旅程或关系；
- 图表标明平台、样本、时间、分母和缺失情况；
- 不为了“看起来专业”增加无结论价值的图表。

## 九、表达要求

- 中文为主，保留必要的英文原词和评论原文；
- 结论先行，但紧跟证据；
- 不用“显然”“证明了”“所有消费者”等超出证据的表达；
- 不把播放量、点赞或评论量解释为销售结果；
- 不把低内容数量直接称为蓝海；
- 对不同证据相互矛盾的地方明确写出；
- 建议必须能够执行，并说明适用前提。

## 十、完成检查

提交前确认：

- 报告范围与用户要求一致；
- 没有擅自补做无关研究；
- 每项核心数字能回到Excel或处理后数据；
- 每项代表观点能回到原视频或原评论；
- 链接不是搜索结果页或无关首页；
- 缺失信息没有被写成零；
- 反例和限制没有被删除；
- 技术结论的专业复核状态清楚；
- 最终建议没有超过研究证据能支持的范围。
